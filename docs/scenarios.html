gruntcmt — scenarios & detail levels

What gruntcmt emits for common terragrunt plans. Use the switch to see every scenario at each fidelity — summary, resource, attribute. Same markdown works in a PR comment and the Actions job summary.

Two surfaces, your call. The markdown goes to a PR comment (≤ 65,536 chars) or the Actions job summary (≤ 1 MiB). You choose the fidelity that fits each: --detail attribute for the roomy summary, --detail summary/resource for the comment. gruntcmt renders exactly what you ask — no truncation, no magic.
Detail
addresses + actions — a good default for the PR comment

🗂️ Grouping depth — --group-by N

Unit names are /-paths. N = how many leading segments form the group key; deeper segments flatten into the unit's label. One level of groups, units flat within. Same 4 units, three depths:

--group-by 0 · flat --group-by 1 · by env (default) --group-by 2 · by env/layer 
(no groups)
production/database/primary
production/database/replica
production/networking
staging/database/db1
 
▾ production
    database/primary
    database/replica
    networking
▾ staging
    database/db1
 
▾ production/database
    primary
    replica
▾ production/networking
    networking
▾ staging/database
    db1

Higher N = more, finer groups. N=0 = one flat list. A unit shorter than N just groups on its whole path as a singleton. Summary-table rows = these groups.
